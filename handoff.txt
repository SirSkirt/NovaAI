NEURAL NOVA V0.5.0 HANDOFF — 2026-10-12
========================================

## v0.5.0 — Learned word units and multi-turn neural memory

This experimental upgrade keeps Neural Nova as **ONE trainable brain** (Transformer + dense network + shared-loss bridge). There is no second chatbot, canned-answer search, arbitrary response selection, or hard-coded semantic lookup.

**Input tokenizer:** `neural-nova/src/tokenizer.rs` provides stable, lossless word-unit tokens with ASCII character fallback for unseen words. Word units are learned from the training split only; words repeated at least twice (3–24 ASCII characters) may enter a 256-slot vocabulary. Token embeddings are part of the Transformer weights and are trained by the existing neural loss. Word-unit IDs never reorder. New words must be trained: they do not arrive with preloaded meaning. **Replies are still decoded/generated character by character**, so this is an input-side tokenizer improvement, not yet a full generative word/subword head. Only ASCII is supported.

**Neural multi-turn memory:** Separate from the 128/256-token attention window, Nova stores the last 64 conversation turns for display and persistence; the last **12 completed turns** are fed to a bounded *neural episodic memory* pathway, one compressed 32-dimensional vector per turn. Learned word/character embeddings are pooled and passed through a trainable tanh write matrix; a learned content-based attention score compares the current hidden representation against each slot; the weighted memory signal is projected into the Transformer's hidden state through a trainable read matrix. Gradients train both the attention interaction and its neural writer/reader. Shared-loss conversation training backpropagates through both memory matrices and past-turn input embeddings, as well as the existing dense pathway and Transformer. Saved turns are *data*, not scripted answers. The teacher does not decide which answer Nova generates. This is an experimental compressed latent memory **not** a proven semantic memory or learned selective-retrieval system; older turns beyond 12 no longer influence neural generation.

**Multi-turn lessons:** Teach → "Multi-turn conversations". Use complete alternated `U: ...` and `N: ...` lines, with blank lines/`---` separating at least five independent sessions of at least two turns each. Validation withholds **whole sessions**. A supervised next-character loss on each Nova reply trains the neural writer/reader only when prior turns exist. Existing text and single-turn dialogue modes remain available. The trainer still only teaches; Nova generates from its own combined weights.

**Persistent chat:** `neural-nova-conversation-v0.5.json` (separate from weights) stores up to 64 completed turns; after app restart, the saved chat is restored. "New conversation" clears conversation records and memory but **does not reset neural weights**. Saving uses a temporary file, sync and backup restoration on rename failures. The 12 most recent turns are passed through trained neural memory embeddings, **not appended to a growing character buffer**.

**Checkpoint migration:** New separate checkpoint `neural-nova-hybrid-0.5.nhyb` stores the expanded Transformer weights (word embeddings and trainable memory matrices), dense weights, both Adam states and stable vocabulary mapping in a `WORDUNIT` trailer. On first launch existing `neural-nova-hybrid-0.4.nhyb` or `neural-nova-hybrid-0.3.nhyb` is migrated **without overwriting the older file**. New word and memory parameters are randomly initialized and need training. Original `main` remains untouched. Reset opt-out marker prevents reimporting prior weights.

**Diagnostics:** The dual-hemisphere visualizer displays actual attention token labels (including learned words), activations and shared bridge. Chat reports original prompt token retention and number of past turns used. The 128 vs 256 comparison uses `commit:false` so neither run modifies conversation history, ensuring comparable memory input. Context still offers 128 or 256 *tokens*, but only tokens learned in the vocabulary are compressed; unseen words fall back to ASCII characters. The dense network retains its 64-character encoder.

**Verification needed:** Code was committed on `experimental/neural-nova`; frontend syntax/API wiring can be checked statically. Native Rust build and on-device Windows/Android training **not yet verified**; do not claim otherwise. Training memory efficacy should be evaluated on unseen multi-turn sessions, not just whether the chat history survives restart.

## v0.4.0 — Context and generation diagnostics

**Why:** Nova sometimes says "Yello!" and sometimes produces gibberish for the same question with unchanged weights. Random sampling and losing the prompt after 128 characters are distinct, testable hypotheses. Neither is proof of language understanding.

- Chat now exposes **reply limit** (32/64/128/192/256 characters), **temperature** (0.2–2.0), **context length** (128/256 characters), and **sampling** (random, fixed seed 42, or most-likely/greedy).
- The **Compare 128 vs 256** button sends the same prompt through the same *joint* hybrid network twice at matching sampling settings/seed and displays side-by-side replies. No training or response selection occurs.
- Every reply reports the amount of the original `U: ...\nN: ` prompt still retained, whether the original prompt began falling out of context, and whether the model ended its reply or hit the length limit.
- The Transformer learned positional embedding array expanded from 128 to 256 positions. Legacy weights, the trainable bridge and both optimizers are migrated; old 128-position embeddings map into the **last** 128 positions so outputs match under the original 128-character setting. The 128 extra positions are initially untrained and need examples reaching them.
- Checkpoint v0.4 is `neural-nova-hybrid-0.4.nhyb`. On the first boot it migrates existing `neural-nova-hybrid-0.3.nhyb` **without overwriting it**. Explicit model resets disable automatic old-checkpoint import, so reset stays reset. Old `main` is unchanged.
- Context option affects **Transformer attention**, not the dense pathway's existing **64-character encoder**, and **does not** add multi-turn conversation memory.
- For a clean experiment, use *Compare* with matched seed or use greedy sampling and inspect the prompt-retention readout. If a reply falls apart before the original prompt is truncated, losing that prompt is not a sufficient explanation. Even if extended context helps, the new untrained positions are a separate variable.

Rust tests include short-input equality between context settings, positional/optimizer migration, end-of-prompt reporting and greedy sampling. CI compilation/device behavior must still be confirmed.

fragmented/gibberish chat and 1,386 shared steps are OLD-LESSON baseline
results, NOT results of the upcoming curriculum. Do not attribute those

Trainer improvements:
- neural-nova/src/trainer.rs prepares text/dialogue samples independently
  of cognition. Dialogue questions are grouped after ASCII case, punctuation

  deterministic hash makes split insensitive to curriculum line order.

- Epoch 1 teaches shorter dialogue contexts before longer ones; later
  epochs shuffle all training characters deterministically. No replies
  are changed or hard-coded.

  ideal reply; 50,000 training tokens and text bytes per CPU session.
- app/src-tauri/src/hybrid_lab.rs now computes a held-out baseline,

  plateaus, early stopping (default patience 6), keeps the best joint
  validation checkpoint, emits training speed, phase and held-out counts.
  Fixed-rate mode remains selectable. Prior v0.3.0 hybrid checkpoints
  are read by the same checkpoint format, not reset automatically.
- neural-nova/src/lib.rs and neural-nova/src/hybrid.rs now accumulate
  dense gradients into a reusable batch buffer instead of allocating
  a full dense gradient array per character; mathematical semantics
  are unchanged. A regression test compares the results.
- Teach tab UI includes learning-rate and adaptive options, best epoch,
  training throughput, lesson split and epoch logs. Chat and Visualize
  remain a single hybrid brain; debugger stays accessible on all tabs.
- Package / native / visible version: 0.3.1.

========================================================================

Data flow:
    input → 64-character dense feature encoding → dense network logits (128)
          → TRAINABLE 32x128 projection ──┐
    input → 128-character Transformer ────┼→ fused hidden state
                                          └→ ONE softmax → ONE generated reply
    One cross-entropy loss is backpropagated through BOTH pathways and the
    32x128 bridge. No separate dense vs Transformer generated messages, no
    voting, no fixed neural association signals, no scripted response fallback.

The dense network retains its existing 1024 → 512 → 512 → 128 topology,
but participates directly in shared-loss training. The Transformer
is still a tiny one-block, one-head ASCII decoder. The bridge is a true
trainable parameter matrix; gradients flow from the shared loss into
both sets of weights. Shared training remains custom Rust/CPU/Adam.

Separate joint checkpoint: neural-nova-hybrid-0.3.nhyb.
It stores Transformer weights + optimizer, dense weights + optimizer, and
the bridge weights (included in Transformer parameter vector). Older
standalone checkpoints are not overwritten or auto-imported. The
standalone v0.2 Transformer loader supports older parameter counts.

UI:
- Teach: editable corpus, dialogue pairs, file import, manual correction,
  epochs, unified training controls, loss/accuracy and progress.
- Chat: ONE Nova reply from the fused network. Correction action moves a
  question to Teach for supervised training, never inserts a canned answer.
- Visualize: stylized left/right brain, genuine last-token attention,
  deterministic subsamples of real dense neuron activations, and actual
  projected bridge signal magnitudes. No invented firing data.
- Debugger: persistent on all tabs, collapsible, auto-opens on errors.

CURRENT ARCHITECTURE (v0.2.0)
=============================
The app includes TWO independent experimental neural architectures:

A) Transformer Language Engine — newer experiment
   Core: neural-nova/src/transformer.rs
   Native app integration: app/src-tauri/src/transformer_lab.rs
   Interface: app/dist/js/transformer.js + app/dist/index.html
   - From-scratch, CPU-reference, single-block causal character decoder.
   - 128 ASCII token IDs (one character per token); context = 128 CHARACTERS,
     not words or subword tokens.
   - Trainable token and right-aligned positional embeddings.
   - Model width 32; one causal self-attention head.
   - Query/key/value/output projections, residual connections, 64-wide ReLU
     feed-forward block, 128-way next-character softmax.
   - Approx. 20,704 trainable parameters (see model.parameter_count()).
   - Manual gradients/backpropagation, Adam, gradient clipping, and a checkpoint
     that includes weights AND Adam optimizer moments/step count.
   - Train modes:
       * Text: next-character prediction on ASCII corpus; 120–14,000 bytes
         per run; last 10% reserved for validation.
       * Dialogue: TAB-separated question<TAB>ideal answer pairs; at least five
         distinct pairs; train only response characters, conditioned on user
         text; reserve final 20% of WHOLE pairs for validation.
   - Reply inference always samples from Transformer model probabilities.
     No call into the legacy model and no canned answers.
   - Separate checkpoint: neural-nova-transformer-0.2.ntrf in experimental
     app's local data folder. It stores optimizer state so training can resume.
   - Attention heatmap displays actual last-query attention weights.
   - Current chat is single-turn; there is no real retained model conversation
     context across earlier turns yet.

B) Legacy dense brain — for comparison only
   Core: neural-nova/src/lib.rs
   Native integration: app/src-tauri/src/neural.rs
   Interface: app/dist/js/brain.js
   - Dense architecture: 1024 -> 512 -> 512 -> 128, 853,120 trainable parameters.
   - v0.1.2+ uses 64 ASCII chars x 16 features for input; 128-way output.
   - ReLU/softmax, custom backpropagation/Adam, training, checkpoints and
     all-2,176-neuron visualizer with sampled real weighted links.
   - Legacy Training Studio: character prediction on text.
   - Legacy Dialogue School: teacher provides question and ideal response;
     model learns response targets; corrections can become more lessons.
   - The owner demonstrated it can reproduce 'My name is Nova.' for the exact
     trained prompt but struggled with capitalization/punctuation/paraphrases.
   - The Transformer does not use the legacy network as a safety net.

KNOWN LIMITATIONS AND HONEST WARNINGS
=====================================
- This is a tiny single-head, single-block, character-level model. It is NOT
  GPT-scale, a trained general chatbot, or a verified reasoning AI.
- Context is 128 characters; very short for useful conversational history.
- Tokenizer supports ASCII, not general Unicode text.
- CPU-only naive Transformer training can be slow on real devices. Larger
  corpora and more epochs are not a substitute for a better architecture.
- The teacher starter corpus (about 30 pairs) is far too small for robust
  language learning or paraphrase generalization.
- Current held-out evaluations can still leak statistical patterns if the
  text repeats; use fully separate unseen datasets and prompt paraphrases.
- Word meaning, multi-turn memory, instruction following, mathematical
  reasoning, and reliable tool use have NOT been established.
- UI displays an in-app debugger at the bottom; preserve and improve this.
  Earlier app versions trained successfully but did not receive progress
  events because Tauri core:event:allow-listen permission was missing.
- Checkpoint formats/encodings differ across dense versions; do not
  accidentally load old weights into a differently encoded model.
- Do not represent a successful GitHub build as a real-device runtime test.
